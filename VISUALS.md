# Что и как визуализируем

Техзадание на графику для главы 6 «Системы управления полётом самолёта».
Редакция 2 — переписана после того, как модель V-11 прошла весь путь
от Blender до живого сайта и показала, что в контракте работает, а что нет.

Этот файл отдаётся исполнителю целиком. На каждую визуализацию есть отдельный
раздел; на сайте под неё уже стоит слот — пунктирная карточка с описанием,
которую видит читатель, пока файла нет.

---

# Часть 1. Контракт

Всё, что здесь написано, проверено на реальной модели. Отступление от любого
пункта означает, что модель придётся переделывать или дорабатывать вьювер.

## Формат и вес

| Что | Формат | Требование |
|-----|--------|-----------|
| 3D-модель | `.glb` (GLTF binary) | один файл, без внешних ресурсов |
| Исходник | `.blend` | прикладывать рядом, он нужен для правок |
| Анимация без 3D | `.svg` с анимацией или Lottie `.json` | до 300 КБ |
| Видео — крайний случай | `.mp4`, H.264, без звука | до 3 МБ, ≤ 12 с |

**Вес `.glb` — до 4 МБ.** Сайт открывают с телефона по QR, часто с мобильного
интернета. Присылайте как есть: сжатие мы делаем на своей стороне командой

```bash
npx @gltf-transform/cli resample вход.glb выход.glb
```

Она убирает избыточные ключевые кадры. На V-11 это дало **12 → 2,9 МБ**
без единого визуального изменения и без декодера в браузере. Draco и meshopt
**не применять** — они требуют декодера, которого во вьювере нет.

## Геометрия

- До ~80 тыс. треугольников. У V-11 было 63 тыс. — достаточный ориентир.
- Оси: **Y вверх, единица = 1 метр**, модель центрирована в начале координат.
- **Камер в сцене не нужно.** Вьювер сам выставляет камеру по габаритам.
- **Источников света не нужно.** Свет ставит сайт: полусферический плюс два
  направленных. Запечённое освещение в материалы не закладывать.
- Текстуры по возможности не использовать: у V-11 их ноль, и это правильно —
  цвет задаётся материалом, вес не растёт.
- **Подвижные детали — отдельными мешами**, не приклеенными к корпусу.

## Имена мешей — латиницей и осмысленно

По именам вьювер подсвечивает узлы и вешает подписи. Без них модель можно
показать, но нельзя по ней кликать.

```
spool, piston, cylinder_body, feedback_rod, port_pressure, port_return
```

Русские названия **в модель не запекать** — они живут в JSON и правятся
без пересборки `.glb`.

**Имена элементов планера.** Всё, что образует внешнюю оболочку, должно
называться по шаблону: `fuselage`, `canopy`, `cowl`, `skin`, `shell`, `glass`,
`window`, `fairing`, `fin`, `wing_*`, `stabilizer_*`. Вьювер узнаёт их
по имени и делает две вещи: **исключает из кликов** (иначе полупрозрачный
фюзеляж перехватывает каждый луч и до механизма не добраться) и вешает
кнопку **«Оболочка»**, которая их прячет. Если имена другие — перечислите
их списком в `opts.shell`.

## Анимационные клипы

Кнопки переключения сценариев сайт строит **сам из имён клипов**. Свой
интерфейс рисовать не надо.

- Имена клипов — **латиницей**: `manual`, `autopilot`, `trim`, `override`.
- Один клип = один законченный учебный сюжет.
- Переход между клипами сайт делает плавным, сшивать их не нужно.
- Если клипов нет, модель просто показывается статично и вращается.

## Подписи

Словарь **имя меша → русская подпись** отдаётся вместе с моделью.
У V-11.2 их 610 — это хороший ориентир по полноте.

**Не забывать планер.** В первой версии V-11 словарь покрывал только механизм,
и клик по фюзеляжу выдавал читателю латиницу `fuselage`. Подписывать надо всё,
по чему вообще можно попасть: `fuselage` → «Фюзеляж, учебный разрез»,
`fin` → «Киль», `stabilizer_r` → «Правая половина стабилизатора».

## Стиль

Сайт светлый, бумажный. Графика — техническая иллюстрация из учебника,
а не игровой рендер.

- Фон прозрачный или белый.
- Корпуса светло-серые `#dee3e9`, металл с лёгким блеском, без хрома.
- Смысловые цвета **одинаковы во всех визуализациях**:
  **синий `#1d5fb8` — давление и активный путь усилия**,
  **серый `#98a3ae` — слив**,
  **зелёный `#16704a` — обратная связь и трение**,
  **красный `#a92920` — усилие, отказ, упоры**.
- Уровень детализации — **учебный разрез, не фотореализм**: оболочка
  полупрозрачная, механизм читается насквозь, болтов и фасок не нужно.

## Как модель попадает на сайт

Кладём `.glb` в `models/`, в нужный `content/*.json` ставим блок:

```json
{
  "t": "figure",
  "name": "model3d",
  "caption": "Подпись под моделью",
  "opts": {
    "src": "models/V-04-rulevoy-privod.glb",
    "scenarios": [
      { "clip": "neutral", "title": "Нейтраль" },
      { "clip": "follow",  "title": "Слежение" }
    ],
    "labels": { "spool": "Распределительный золотник" },
    "shell": ["fuselage_cut"]
  }
}
```

Удобнее всего прислать **готовый файл `V-XX-integration.json`** такой же формы —
как было с V-11. Тогда подключение сводится к копированию.

## Что уже умеет вьювер

Ленивая загрузка Three.js только на страницах с моделью, автокадрирование
по габаритам, вращение и зум, кнопки «+» и «−» (на телефоне колеса нет),
режим «Сдвиг» для перемещения одним пальцем, кнопка «Оболочка», «Сброс вида»,
клик по детали с русской подписью, остановка рендера когда модель ушла с экрана.

## V-04 · Рулевой привод в разрезе

**Главная модель всей главы.** Страница **6.2 «Бустерное управление»**, `#fc-booster`.
Соответствует рис. 6.25 методички.

### Зачем

Это ядро темы. Если студент понял следящий золотник один раз, он узнает его
потом в приводе стабилизатора, в механизации, в поворотe колёс и в ЭДСУ.
На эту модель стоит потратить больше времени, чем на все остальные вместе.

### Что должно быть в кадре

- **Командный рычаг пилота** и тяга от него к золотнику.
- **Распределительный золотник** — три пояска, между ними окна.
- **Корпус распределителя** с тремя каналами: `P` — давление,
  два `T` — слив.
- **Силовой цилиндр**, жёстко **закреплённый в конструкции самолёта**.
  Точку крепления показать явно: именно она поглощает шарнирный момент,
  и именно поэтому схема называется необратимой.
- **Поршень и шток**, шток идёт к поверхности управления.
- **Тяга обратной связи** от штока к рычагу суммирования.
- **Рычаг суммирования** с тремя точками: вход от пилота, выход на золотник,
  обратная связь от штока.
- **Поверхность управления** на конце штока.
- **Жидкость** в полостях, окрашенная по смыслу.

### Что обязано читаться

Главная мысль: **золотник закрывается сам**. Отдельной команды «стоп» нет.
Он открыт ровно настолько, насколько шток ещё не дошёл до заданной точки.
Если это не считывается — модель не выполнила задачу, как бы красиво
она ни выглядела.

### Клипы

| Клип | Что происходит |
|------|----------------|
| `neutral` | Рычаг неподвижен, золотник в нейтрали, жидкость **заперта в обеих полостях**, шток зафиксирован |
| `follow` | Полный цикл: рычаг пошёл → золотник сдвинулся → одна полость к `P`, другая к `T` → шток идёт → обратная связь возвращает золотник в нейтраль → движение прекратилось |
| `hold` | Пилот остановил рычаг **на полпути**: шток надвигается на золотник, окна перекрываются, поверхность замирает в промежуточном положении |
| `reverse` | Рычаг в обратную сторону: золотник подаёт давление в другую полость, обеспечивает слив из первой, шток идёт назад |

Клип `hold` важнее, чем кажется: он показывает, что привод отрабатывает
**положение**, а не команду «двигайся».

### Имена мешей

```
command_lever, input_rod, summing_lever, pin_input, pin_spool, pin_feedback
spool, spool_land_1, spool_land_2, spool_land_3, valve_body
port_pressure, port_return_l, port_return_r
cylinder_body, piston, rod, airframe_mount, feedback_rod
surface, surface_hinge
fluid_pressure, fluid_return_l, fluid_return_r
```

### Чего не делать

Не изображать гидроусилитель «чёрным ящиком» со стрелками. Вся ценность —
в разрезе: видно пояски золотника, видно окна, видно, как обратная связь
физически тянет рычаг.

## V-05 · Загрузочное устройство, МЭТ и механизм *K*ш

Страница **6.2 «Бустерное управление»**, `#fc-booster`. Рис. 6.24 методички.

### Зачем

Модель V-04 сама порождает вопрос: если руль двигает гидравлика, а пилот
шевелит только золотник — откуда усилие на ручке? V-05 отвечает. Это место,
где студенты путаются чаще всего, и на защите его спрашивают.

### Что должно быть в кадре

- **Рычаг пилота**.
- **Загрузочное устройство** — пружина, сжимаемая при отклонении рычага.
- **Качалка загрузочного механизма с переменным плечом** — то самое
  «переменное плечо действия на загружатель» с рисунка.
- **Механизм *K*ш** и его электромеханизм, меняющий плечо качалки
  в зависимости от скорости и высоты.
- **МЭТ** — электромеханизм триммерного эффекта; его **шток образует
  опорную точку для загрузочного устройства**.
- **Гидроусилитель** (упрощённо, без разреза — он подробно показан в V-04).
- **Поверхность управления**.
- **Указатель усилия на рычаге** — столбик или стрелка сбоку, меняющийся
  в реальном времени. Без него сюжет не читается.

### Клипы

| Клип | Что происходит |
|------|----------------|
| `deflect` | Пилот отклоняет рычаг: пружина сжимается, указатель усилия растёт пропорционально отклонению |
| `speed_up` | Растёт скорость полёта: электромеханизм **уменьшает плечо качалки**, при том же отклонении усилие на рычаге заметно выше |
| `trim` | Пилот нажимает переключатель МЭТ: **шток МЭТ едет, пружина разжимается**, указатель усилия падает до нуля — при этом **поверхность остаётся отклонённой** |
| `autotrim` | То же самое, но команду даёт автопилот |

Ключевой кадр — `trim`: усилие ушло в ноль, а руль не вернулся. Это и есть
разница между триммированием и возвратом в нейтраль.

### Имена мешей

```
pilot_lever, load_spring, load_rod, ksh_bellcrank, ksh_arm, ksh_motor
mte_body, mte_rod, mte_anchor
booster_body, booster_rod, surface
force_indicator, force_scale
```

## V-06 · Сервопривод элеронов A320: активный режим и демпфирование

Страница **6.2 «ЭДСУ и автоматизация»**, `#fc-fbw`. Рис. 6.28 методички.

### Зачем

Показывает, что ЭДСУ не изобрела новый привод: внутри тот же золотник
и тот же шток, что в V-04. Изменилось только то, что подаёт команду.
Плюс здесь единственное место в главе, где виден режим демпфирования.

### Что должно быть в кадре

Привод в разрезе. Узлы — по нумерации методички, её же держать в подписях:

1. **Электромагнитный клапан**
2. **Головка управления**
3. **Впускной клапан**
4. **Выпускной клапан**
5. **Клапан слива** (обратный предохранительный)
6. **Запас жидкости** — резервный резервуар
7. **Клапан переключения режимов** (селектор) с возвратной пружиной
8. **Следящий датчик режимов LVDT**
9. **Демпфирующий жиклёр**
10. **Обратный клапан**
11. **Следящий датчик обратной связи LVDT**

Плюс поршень, шток, две камеры, элерон.

### Клипы

| Клип | Что происходит |
|------|----------------|
| `active` | Электромагнитный клапан под питанием от **ELAC**, селектор в активном положении, камеры подключены к сервоклапану, поток окрашен, шток движется, LVDT показывает положение |
| `damping` | Клапан **обесточен**, селектор ушёл под действием своей пружины, **камеры соединены через демпфирующий жиклёр**; шток поддаётся внешнему усилию, но с сопротивлением |
| `hydraulic_failure` | Запорные клапаны закрывают и **изолируют привод** от гидросистемы самолёта |

В `damping` должно читаться, что отказавший привод не бросает поверхность
болтаться и не мешает исправному: он превращается в гидравлический амортизатор.
Это защита от флаттера в чистом виде.

### Имена мешей

```
solenoid_valve, control_head, inlet_valve, outlet_valve, drain_valve
fluid_reserve, mode_valve, mode_spring, lvdt_mode, damping_jet
check_valve, lvdt_feedback, piston, rod, chamber_a, chamber_b, aileron
```

## V-08 · Трансмиссия механизации и защита от рассинхронизации

Страница **6.3 «Вспомогательные системы»**, `#fc-aux`. Рис. 6.43–6.45 методички.

### Зачем

Единственная система в главе, где отказ парируется **механическим тормозом**,
а не переключением на резерв. Хороший контраст к ЭДСУ.

### Что должно быть в кадре

Крыло сверху, полупрозрачное:

- **Рукоятка FLAPS** с блоком командных сенсоров.
- **Два компьютера** управления механизацией.
- **Гидромотор и электромотор**, сведённые через **дифференциальный редуктор**
  на общий выходной вал — два независимых канала на одно выходное звено.
- **Вал трансмиссии** вдоль крыла в обе стороны.
- **Винтовые подъёмники** на каждой секции — преобразуют вращение вала
  в поступательное движение закрылка.
- **Датчики положения** на концах трансмиссии.
- **Тормоза Wing Tip Brake** на концах вала.
- **Закрылки и предкрылки**, движущиеся по направляющим рельсам.
- **Индикатор положения** сбоку — зелёные стрелки S и F, как на ECAM.

### Клипы

| Клип | Что происходит |
|------|----------------|
| `extend` | Выпуск: рукоятка в положение, вал вращается, подъёмники двигают закрылки **назад и вниз**, по достижении положения приводы отключаются и **фиксируют трансмиссию встроенными тормозами** |
| `retract` | Уборка |
| `asymmetry` | Отказ: одна половина отстаёт, **рассогласование растёт** → сигнализация → привод останавливается → **срабатывают Wing Tip Brake**, фиксируя вал. На индикаторе видно, что расхождение **не превысило 2°** |

### Имена мешей

```
flaps_lever, sensor_unit, computer_1, computer_2
motor_hydraulic, motor_electric, differential_gearbox
torque_shaft_l, torque_shaft_r, screwjack_l1, screwjack_l2, screwjack_r1, screwjack_r2
ppu_l, ppu_r, wtb_l, wtb_r
flap_l, flap_r, slat_l, slat_r, track_l, track_r
indicator_flaps, indicator_slats
```

## V-09 · Винтовой подъёмник стабилизатора

Страница **6.3 «Вспомогательные системы»**, `#fc-aux`. Рис. 6.47, 6.48 методички.

### Зачем

Показывает, почему на магистральном самолёте отдельный аэродинамический
триммер руля высоты может вообще отсутствовать — его роль выполняет
весь стабилизатор.

### Что должно быть в кадре

Механизм в разрезе:

- **Корпус**, **ведущая и ведомая шестерни**, большое передаточное число.
- **Гайка** — показать, что она бронзовая, в титановом стакане.
- **Ходовой винт** с малым шагом резьбы — отсюда **эффект самоторможения**,
  который удерживает стабилизатор в любом промежуточном положении.
- **Дублирующий стяжной стержень внутри полого винта** — рассчитан
  на 100 % нагрузки при поломке винта.
- **Карданные узлы крепления** сверху и снизу, **упоры**.
- **Стабилизатор** и **лонжерон киля**.

### Клипы

| Клип | Что происходит |
|------|----------------|
| `nose_up` | Винт вращается, гайка идёт, стабилизатор переставляется на кабрирование |
| `nose_down` | На пикирование |
| `self_lock` | Привод остановлен, на стабилизатор действует аэродинамическая нагрузка — **винтовая пара держит**, самоторможение |
| `screw_failure` | Ходовой винт разрушен, **дублирующий стержень удерживает стабилизатор** — подсветить его отдельно |

### Имена мешей

```
gearbox_housing, drive_gear, driven_gear, nut_bronze, nut_cup_titanium
screw_hollow, tie_rod_backup, cardan_upper, cardan_lower
stop_up, stop_down, stabilizer, fin_spar, screwjack_mount
```

## V-07 · Боковые ручки: связанные и независимые

Страница **6.2 «ЭДСУ и автоматизация»**, `#fc-fbw`. Приоритет низкий.

### Что должно быть в кадре

Две боковые ручки рядом — левая и правая, с пружинными загружателями,
демпферами, датчиками, замками с электромагнитом и балансировочным грузом.

### Клипы

| Клип | Что происходит |
|------|----------------|
| `independent` | Классический Side Stick A320: двигаем одну — вторая **стоит**. Рядом всплывает логика приоритета: отклонение в одну сторону — берётся большее, **в разные стороны сигнал не проходит**, кнопка TAKE OVER отдаёт приоритет |
| `linked` | Активные сайдстики A350 и УБРУ МС-21: двигаем одну — **вторая повторяет синхронно** через электрическую связь |
| `shaker` | Ручка вибрирует при угрозе сваливания |

### Имена мешей

```
stick_l, stick_r, spring_load_l, spring_load_r, damper_l, damper_r
sensor_pitch_l, sensor_roll_l, lock_solenoid_l, balance_weight_l
link_electronic, button_takeover_l, button_takeover_r
```

# Часть 4. Что в 3D делать не надо

Здесь 3D почти ничего не добавляет, а времени съедает столько же.
Если очень захочется — только после того, как сделаны V-04, V-05 и V-06.

## V-01 · Поверхности управления самолёта
Страница `#fc-intro`. Это **подписанная схема**, а не механизм: элероны, РВ, РН,
стабилизатор, закрылки, предкрылки, спойлеры, тормозные щитки, щитки Крюгера.
Статичная картинка с выносками решает задачу полностью. На сайте уже есть
схема цепочки «команда → проводка → привод → поверхность».

## V-02 · Три вида проводки в разрезе
Страница `#fc-direct`. Жёсткая тяга, трос 7×19, боуденовский трос.
Закрыто взрыв-схемой из руководства по ТО (рис. 1 подраздела 27-00),
она точнее любой модели. Детали жёсткой тяги вдобавок уже есть в V-11.

## V-03 · Пять способов компенсации
Страница `#fc-comp`. **На сайте уже стоит интерактивная схема** с переключением
между осевой, роговой, внутренней компенсацией, сервокомпенсатором
и антисервокомпенсатором, с индикатором усилия. Переключать самому полезнее,
чем смотреть ролик.

## V-10 · Три способа стопорения
Страница `#fc-lock`. Струбцина, Gust Lock в кабине DA 42, электромеханический
стопор в нервюре. Три фотографии решают задачу лучше и бесплатно —
снимки уже есть в `_ref-da40/`.

Собственные интерактивные схемы на inline SVG. Они останутся и после

| Схема | Страница | Что показывает |

# Порядок работы

1. **V-04** — гидроусилитель. Начинать с него.
2. **V-05** — загрузочное устройство и МЭТ.
3. **V-06** — сервопривод A320.
4. Второй проход по **V-11.2** по списку читаемости.
5. Дальше **V-08**, **V-09**, при желании **V-07**.

Для защиты достаточно комплекта **V-11 + V-04 + V-05**: механика →
гидроусилитель → почему пилот всё равно чувствует руль. Это законченная
линия рассуждения, а не набор разрозненных моделей.
